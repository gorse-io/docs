# Go 1.27 SIMD 性能测试：能否替代手写 AVX512？

Go 1.27 引入了实验性的 [`simd`](https://pkg.go.dev/simd) 包，为整数和浮点数提供了可移植、与向量宽度无关的 SIMD 类型和运算。过去，Gorse 为了加速模型训练和推理中的向量计算，使用 [GoAT](https://github.com/gorse-io/goat) 将 C 语言编译生成的 AVX、AVX512、NEON 等指令转换为 Go 汇编。`simd` 包让同一套 Go 代码在不同指令集上运行成为可能，但它的性能能否接近专门优化的汇编实现？

本文基于 Gorse `common/floats` 包的 256 组基准测试结果，对比以下四种实现：

- **AMD64**：不显式启用 SIMD 特性的基础实现；对于本文的向量运算，可以视为普通 Go 标量循环。
- **AVX**：由 C 代码编译并通过 GoAT 转换得到的 256 位 AVX 汇编。
- **AVX512**：由 C 代码编译并通过 GoAT 转换得到的 512 位 AVX512 汇编。
- **Go SIMD**：使用 Go 1.27 实验性 `simd` 包编写的实现。

测试代码已经提交到 [gorse-io/gorse#1374](https://github.com/gorse-io/gorse/pull/1374)。

## 实验环境与方法

实验环境如下：

| 项目 | 配置 |
|---|---|
| 操作系统 | Windows / amd64 |
| CPU | 11th Gen Intel Core i7-11370H @ 3.30 GHz |
| Go | 1.27.0 |
| Go SIMD 向量宽度 | 512 位，即 16 个 `float32` |
| Go SIMD 模式 | 硬件执行，非模拟模式 |
| 输入长度 | 16、32、64、128 个 `float32` |
| 矩阵阶数 | 16、32、64、128 |

运行全部基准测试的命令为：

```powershell
$env:GOEXPERIMENT = "simd"
go test ./common/floats -run '^$' -bench . -count=1
```

表格中的数值均为 `ns/op`，越低越好。“相对 AMD64”和“相对 AVX512”分别使用 `AMD64 耗时 / Go SIMD 耗时` 与 `AVX512 耗时 / Go SIMD 耗时` 计算：大于 1 表示 Go SIMD 更快，小于 1 表示 Go SIMD 更慢。汇总加速比使用几何平均数。

需要注意，本次数据来自一次完整运行。它适合观察数量级和总体趋势，但没有给出置信区间；几个纳秒以内的差异容易受到 CPU 频率、温度和操作系统调度影响。

## Go SIMD 实现

以原地向量减法为例，Go SIMD 实现先处理完整向量，再使用部分加载和存储处理任意长度的尾部：

```go
func simdSub(a, b []float32) {
	vectorLen := simd.VectorBitSize() / 32
	for len(a) >= vectorLen {
		simd.LoadFloat32s(a).Sub(simd.LoadFloat32s(b)).Store(a)
		a = a[vectorLen:]
		b = b[vectorLen:]
	}
	if len(a) > 0 {
		x, n := simd.LoadFloat32sPart(a)
		y, _ := simd.LoadFloat32sPart(b)
		x.Sub(y).StorePart(a[:n])
	}
}
```

Go 编译器会为同一个函数生成不同向量宽度的版本，例如 `simdSub@simd128`、`simdSub@simd256` 和 `simdSub@simd512`，运行时再选择合适的实现。本次实验选择了 512 位版本；反汇编结果也确认核心路径使用了 ZMM 寄存器和 `VSUBPS` 指令。因此，下面的性能差异并不是 Go SIMD 回退到标量实现造成的。

### 向量运算汇总

| 长度 | 相对 AMD64 几何平均加速 | 相对 AVX | 相对 AVX512 | 胜过 AVX512 的操作数 |
|---:|---:|---:|---:|---:|
| 16 | 2.70x | 0.91x | 0.89x | 6/12 |
| 32 | 3.82x | 0.75x | 0.70x | 0/12 |
| 64 | 4.99x | 0.69x | 0.62x | 0/12 |
| 128 | 6.16x | 0.65x | 0.53x | 0/12 |

从结果可以得到以下结论：

1. **Go SIMD 相比普通 Go 循环有稳定且显著的收益。** 随着向量长度从 16 增加到 128，几何平均加速比从 2.70 倍上升到 6.16 倍。向量越长，固定调用开销越容易被摊薄，SIMD 并行计算的优势也越明显。
2. **短向量下，Go SIMD 已经能够接近甚至超过手写 AVX512。** 长度为 16 时，Go SIMD 在 12 个操作中的 6 个操作上快于 AVX512，其中 `MulConstAdd` 快约 22%，`MulConstAddTo` 快约 13%。不过这一级别的差异只有约 1 ns，单次测试不足以证明 Go SIMD 稳定领先。
3. **长向量下，手写 AVX512 仍然明显更快。** 长度为 128 时，Go SIMD 相对 AVX512 的几何平均比值为 0.53，即整体耗时约为 AVX512 的 1.89 倍。差距最大的 `MulTo` 和 `Sub` 分别约慢 3.20 倍和 2.80 倍。
4. **昂贵指令更容易掩盖循环管理开销。** 长度为 128 时，Go SIMD 的 `DivTo` 和 `SqrtTo` 分别只比 AVX512 慢约 15% 和 16%；除法和平方根本身的指令延迟较高，切片重切、边界检查和循环跳转占总耗时的比例更低。
5. **归约操作仍是明显短板。** `Dot` 和 `Euclidean` 需要将 SIMD 累加器保存到临时数组，再用标量代码进行横向求和。长度为 16 时，`Dot` 甚至慢于普通 Go 实现；在其他长度下虽然仍比 AMD64 基础实现快，但与 AVX512 的专用横向归约存在较大差距。

Go SIMD 的 512 位版本确实生成了 `VMOVDQU64`、`VSUBPS` 等 AVX512 指令，但当前 Go 写法每处理 16 个元素仍然需要维护切片长度和容量、执行循环判断，并保留边界检查与尾部路径。相比之下，C 编译生成的汇编使用更紧凑的指针循环，还可能进行循环展开。这解释了为什么“使用 AVX512 指令”并不自动等价于“达到手写 AVX512 实现的性能”。

Go SIMD 矩阵乘法并不是完整的高性能 GEMM 实现，而是复用 `simdMulConstAdd` 和 `simdDot` 的朴素三重循环。它没有进行缓存分块、矩阵打包、循环展开或多累加器调度，因此结果与高度优化的矩阵乘法库不具可比性。本组数据更适合观察“将已有向量函数直接组合成矩阵乘法”的成本：

- 对 16 到 64 阶矩阵，Go SIMD 与 AMD64 标签实现的几何平均性能大致相当；到 128 阶时反而慢约 35%。
- Go SIMD 仅达到 AVX512 实现约 27%～32% 的几何平均性能，即耗时约为 AVX512 的 3.1～3.7 倍。
- `NT` 分支依赖 `simdDot`，会重复承担横向归约开销，因此表现最弱。
- `TT` 分支访问不连续，当前实现没有直接使用 SIMD 指令。它相对 AMD64 标签实现的收益主要来自循环顺序和访存行为，而不是向量化。

如果需要真正高性能的矩阵乘法，应该优先使用经过分块、打包和多线程优化的 BLAS 实现。可移植 SIMD 更适合加速 Gorse 中大量短小、结构简单的向量算子。

## 应该选择哪种实现？

综合本次实验，可以得到一个相对清晰的选择顺序：

1. **优先考虑可维护性和跨架构支持时，Go SIMD 很有吸引力。** 一份代码可以根据运行时能力选择 128、256 或 512 位向量，还能自动处理硬件不支持时的模拟路径。与普通 Go 循环相比，本文测试中的加速通常达到数倍。
2. **追求固定平台上的极致性能时，专门优化的汇编仍然占优。** 手写或由编译器生成的 AVX512 循环可以更精确地控制指针、展开和归约方式。在 128 元素向量上，Go SIMD 的几何平均耗时仍接近 AVX512 的两倍。
3. **复杂算法不能只替换最内层运算。** 矩阵乘法的性能更多取决于缓存分块、数据布局和循环组织。仅把标量运算替换成 SIMD，无法自动获得高性能 GEMM。
4. **实验性 API 适合验证，不宜马上删除成熟汇编路径。** `simd` 目前仍需要 `GOEXPERIMENT=simd`。更稳妥的演进方式是保留现有汇编作为性能基线，同时持续跟踪编译器对循环、边界检查和横向归约的优化。

## 总结

Go 1.27 的实验性 `simd` 包已经解决了 Go 语言长期缺少可移植 SIMD API 的问题。它确实能够在本次测试机器上生成并执行 AVX512 指令，并将普通 Go 向量循环加速 2.70～6.16 倍。对于希望兼顾性能、可读性和跨架构能力的项目，这是一个非常有价值的进步。

不过，可移植性并不是免费的。当前 Go SIMD 实现在长向量、横向归约和矩阵乘法中仍然落后于专门优化的 AVX512 汇编。现阶段更合理的结论不是“Go SIMD 已经替代手写汇编”，而是“Go SIMD 已经成为普通 Go 与极致汇编优化之间一个实用的新选择”。
